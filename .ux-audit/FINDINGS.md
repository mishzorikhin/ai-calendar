# UX Audit — AI Календарь

Date: 2026-10-20 · Viewport: 390×844 mobile-first (desktop spot-check at 1440×900) · Persona: first-time user
Target: `http://localhost:5173` (Vite dev server — **current source**; `/api` proxied to the Go backend on :8080)

> ⚠️ Environment note: the Go server running on :8080 is a **stale build** — it serves an older
> frontend and an older API (missing `GET /api/tasks`, `POST /api/chat` — both exist in current
> `server/internal/api/api.go`). Findings below were collected against current frontend source;
> backend-mismatch items are marked **[stale-backend]** where the trigger is environmental, but the
> UX defect they reveal is real.

## Executive Summary

**Totals: 7 High · 8 Medium · 6 Low (21 findings)**

The app is beautiful, motion is tasteful, the composer/sheet patterns are genuinely good — but the
first-time experience is undermined by four systemic problems:

1. **The flagship feature fails ungracefully.** Sending any assistant message shows a raw backend
   error (`Метод API не найдено`) as a fake "assistant reply", the user's own message never posts,
   and a refetch erases all evidence of the failure. The user cannot tell what happened.
2. **Silent degradation.** When `/api/tasks` fails, Home shows "Задач пока нет" — pixel-identical
   to a real empty state. Nothing tells the user tasks are broken, while the console fills with
   retry noise. Failure and emptiness look the same everywhere in this app.
3. **Fabricated demo content leaks into a real user's session.** The chat is pre-seeded with a fake
   conversation in which the assistant claims it booked restaurant tables ("Бронь A-4822") and
   texted a contact ("Глебу отправил приглашение") — side effects that never happened, plus a
   literal garbage message ("Поа"). A new user reasonably concludes the app acts on their behalf
   without asking, or that someone else's account is showing.
4. **A calendar that can't hold a full day.** Manual event creation is capped to starts between
   08:00 and 20:00 in 30-minute steps — while the app's own seeded data contains 06:00 (Сон) and
   22:00 (Чтение) events the UI can display but not create.

**Top 5 to fix first:** H-1 (chat failure UX), H-4 (time input range), H-3 (seeded fake history),
H-5/H-6 (overlapping display text — a systematic card-header layout bug seen in two places),
H-2 (silent task-backend failure).

**Coverage.** Exercised: home, month, day (timeline + list modes), chat, event composer
(create/edit/delete/delegate/free-time prefill), task sheet, voice overlay, first-run hint,
month picker, week/day navigation, all three `?action=` launch URLs, refresh behavior, dark-scheme
emulation, reduced motion, desktop viewport. Not exercised: real speech recognition (no mic in
audit browser), real LLM response (backend 404), PWA install prompt / service worker update /
offline badge (not triggerable in this context), external booking/invite integrations.
