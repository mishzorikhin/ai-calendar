# AGENTS.md — инструкция для кодовых агентов

Этот файл — основной источник правил для любого агента (Claude Code, Codex, Cursor, Copilot и др.).
Человеческое описание проекта — в `README.md`; правила бэкенда — в `server/AGENTS.md`;
чек-лист ревью — в `REVIEW.md`.

## Как пользоваться инструкциями

- Перед изменениями прочитайте этот файл; для `server/` дополнительно — `server/AGENTS.md`, для `kmp/` — `kmp/AGENTS.md`.
  `CLAUDE.md`, `.cursor/rules/project.mdc` и `.github/copilot-instructions.md` — короткие точки входа,
  общие правила меняйте здесь, а не копируйте целиком в каждый файл.
- Команды и фактическое поведение сверяйте с `package.json`, `Makefile`, `vite.config.ts`,
  `.github/workflows/` и исходниками. Документация не заменяет проверку реализации.
- Сначала проверьте текущую ветку и `git status`; сохраняйте чужие незакоммиченные изменения.
  Не считайте, что рабочая ветка всегда называется `main`.
- Выполняйте согласованную задачу до конца. Деплой на сервер — отдельное действие, только по явной просьбе;
  отправка коммита в GitHub сама по себе не означает разрешение на деплой.

## Что это за проект

Мобильный AI-календарь (PWA). Пользователь пишет или диктует ассистенту («поставь встречу с Глебом
на завтра после обеда»), а тот через инструменты смотрит расписание, ищет свободные окна и
создаёт, меняет и удаляет события и задачи.

- **Фронтенд** — React 19 + TypeScript (strict) + Vite 8 + framer-motion + CSS Modules + TanStack Query, PWA (свой service worker `src/sw.ts`, Workbox через `injectManifest`).
- **Бэкенд** — Go 1.24 (`server/`): стандартная библиотека + `pgx/v5` для PostgreSQL. Хранилище — JSON-файл или PostgreSQL (если задан `DATABASE_URL`).
- **Аккаунты** — регистрация и вход по логину и паролю, Bearer-токен. События и чат личные; **задачи и цели** можно делить с другими (`@логин` в тексте или список участников), участники получают уведомления.
- **Ассистент** — настоящий LLM с function calling (OpenAI-совместимый API, SSE-стрим), `server/internal/llm` + `POST /api/chat`. Без `LLM_API_KEY` отвечает заглушкой.
- **Офлайн** — мутации событий и задач при обрыве сети ждут в очереди (`api/outbox.ts`, IndexedDB) и доигрываются сами.
- **Внешние календари** — Google и Outlook (OAuth), CalDAV (Яндекс, iCloud, Nextcloud), подписки `.ics` и своя лента `.ics`
  наружу (`server/internal/calsync`, UI — `screens/home/calendars`). Их события лежат рядом со своими (`source`).
- **Уведомления** — Web Push со своего сервера без сторонних аккаунтов: VAPID и шифрование в `server/internal/webpush`,
  напоминания о встречах, сроках задач и план на день — `server/internal/api/reminders.go`, показ и кнопки — `src/sw.ts`,
  UI — `screens/home/reminders` и лента «Напомнить» в шторке события.
- **Клиент на Kotlin Multiplatform** (`kmp/`) — те же экраны нативно: Android, iOS и веб (Wasm) на Compose Multiplatform,
  тот же Go-сервер. Правила — `kmp/AGENTS.md`, запуск — `kmp/README.md`. Веб-PWA остаётся эталоном внешнего вида.
- **Два режима данных:** серверный и локальный (моки + `localStorage`, без аккаунта — для GitHub Pages и работы над UI).
- **Поставка** — один Docker-образ: Go-бинарник со встроенным UI (`go:embed`); `docker-compose` поднимает ещё и PostgreSQL 17.
- **Главное в продукте — дизайн и анимации.** Визуальное качество важнее количества функций.

Без запущенного Go-сервера UI сам переходит в **локальный режим** (моки + `localStorage`, без входа),
поэтому для работы над интерфейсом сервер не обязателен. Явно: `VITE_API_MODE=local|server`,
адрес бэкенда на другом домене — `VITE_API_URL`. Если приложение уже работало с сервером, а сеть
пропала, оно остаётся в серверном режиме (кэш + офлайн-очередь), а не откатывается к моками.
Без `LLM_API_KEY` чат отвечает заглушкой; в `make api` ключ можно передать через окружение.
Vitest сейчас выполняет `src/**/*.test.ts` в Node: браузерные сценарии и service worker этим не проверяются.
PostgreSQL-тесты очищают таблицы: используйте отдельную одноразовую тестовую БД, никогда рабочую.

React-компоненты; `mocks/` используются только в `api/local.ts` и как контент подсказок чата.

## Архитектурные правила

1. **Данные — только через `api/queries.ts`.** Не вызывайте `fetch` из компонентов и не импортируйте
   `mocks/calendar` в экраны. Новый эндпоинт = метод в `CalendarApi` (`api/api.ts`) +
   реализация в **обоих** `http.ts` и `local.ts` + хук в `queries.ts` + ключ в `keys` + инвалидация.
   Если это мутация событий или задач — решите, как она ведёт себя офлайн (`offline.ts`/`outbox.ts`:
   операция в очереди, временный id `offline-*`, склейка правок, `dedupe` для create), и добавьте тест.
2. **Контракт API в двух местах:** Go `server/internal/model` ↔ TS `src/domain/types.ts`
   (+ DTO-преобразования в `api/http.ts`). Меняете поле — меняйте обе стороны и тесты обеих сторон.
   Лимиты длин — `domain/limits.ts` ↔ `server/internal/api/api.go`. Месяц в TS и в `CalendarApi` —
   с 0 (как `Date`), в `/api/month` — с 1.
3. **`local.ts` повторяет правила сервера** (валидация, лимиты), чтобы UI вёл себя одинаково в обоих
   режимах. Исключение: аккаунтов в локальном режиме нет, шаринг задач и уведомления там заглушены.
4. **Сессия:** токен и пользователь лежат в `api/session.ts` (localStorage, общая для вкладок);
   обычный HTTP-клиент сбрасывает её по `401` (`app/session-gate` показывает вход). У потока чата
   и replay очереди отдельные пути обработки ошибок — проверяйте их отдельно. Токен дублируется
   в метаданные outbox — его читает service worker; там же владелец очереди (операции помечены автором,
   вход другого пользователя стирает чужие), а кэш `api` service worker стирается при смене пользователя.
   Не добавляйте другие копии и не логируйте токен.
5. **Нижняя панель:** экран рендерит `<BarSlot id="…" hidden? aiActive?>…</BarSlot>` (портал).
   Не кладите JSX в глобальное состояние. `BarSlot` — на верхнем уровне экрана, не внутри
   вложенных `AnimatePresence`.
6. **Модальные окна — только через `components/BottomSheet`** (Escape, фокус-ловушка, `inert` фона,
   свайп вниз за любое место). Не копируйте разметку шторки.
7. **События внешних календарей** — `CalendarEvent.source` (id подключения), `readOnly`, `allDay`.
   `useDayEvents` отдаёт события со временем в `events`, а на весь день — отдельно в `allDay`: шкала, окна
   и «Далее» их не учитывают. `readOnly` открывается в `ReadOnlyEvent`, а не в редакторе. Подключения —
   хуки `useIntegrations`/`useCreateIntegration`… в `queries.ts`; после их изменений инвалидируются и дни,
   и месяцы. Новый вид календаря — сначала провайдер в `server/internal/calsync`, затем вариант в
   `ConnectOptions`. В локальном режиме календари не подключаются (как и аккаунты).
8. **Чат** — `screens/chat`: ответ приходит потоком `ChatEvent` (`open`/`delta`/`tool`/`done`/`error`) через
   `CalendarApi.sendChat`; реплики сохраняет сервер. `open` шлёт сам клиент API, когда сервер принял реплику:
   ошибка после него — «ответ оборвался», а не «не отправлено». Перед `done` может прийти `memory` — что запомнилось
   за ход (пометка «Запомнил: …» под ответом). Поток в офлайн-очередь **не** кладётся — у
   него свой UI ошибки и повтора. После вызова инструмента инвалидируйте кэш событий/задач. Удаления
   и массовые переносы ассистента выполняет только кнопка: инструмент шлёт в поток `confirm`, карточка
   (`screens/chat/ConfirmCard`, `useChatConfirms`) отвечает `POST /api/chat/confirms/{id}` (`confirm.go`).
   Реплики пишут только `POST /api/chat` и ответ на карточку; уход из чата прерывает чтение, но сервер допишет ответ.
9. **Доменная логика — чистые функции в `domain/`** с тестами рядом (`*.test.ts`).
10. **Даты:** в состоянии — `Date` начала суток (`startOfDay`), в API — строка `ГГГГ-ММ-ДД`
    (`toISODate`/`fromISODate`). Время внутри дня — минуты от полуночи (`number`).
11. **Склонения и подписи дней** — `lib/plural.ts` и `relativeDayLabel` из `lib/dates.ts`; не пишите
    свои `n % 10`.
12. **Уведомления.** Содержимое push — `model.PushMessage` на сервере ↔ `src/pwa/pushMessage.ts`; меняете поле — меняйте
    обе стороны. `CalendarEvent.reminders`: `null`/нет поля — как в настройках (`NotifySettings.eventReminder`),
    `[]` — не напоминать; в `PATCH` `null` возвращает значение по умолчанию. Подписка устройства привязана к аккаунту
    (`api/push.ts`): выход снимает её, а при входе другого человека чужая подписка не переходит к нему.
    Запросы из service worker (кнопки уведомления) берут токен из метаданных очереди (`outbox.authToken()`).
    Если окно приложения в фокусе, worker в Chromium (вне iOS) не показывает системное уведомление, а шлёт `push:show`
    (`pwa/PushToast`); Chromium это допускает. В Safari, PWA на iPhone и Firefox системное показывается всегда.
13. **Участники встреч** — `CalendarEvent.attendees` (у своих) и `invite` (у чужих, куда позвали; `readOnly`, открывается
    в `ReadOnlyEvent` с «Приду / Не приду», `useRsvp`). Сервер: `api/attendees.go`, приглашения входят в `eventsBetween`,
    отклонённые — нет. Уведомление о встрече несёт `eventId`/`date` — по нажатию открывается день.
14. **Персонализация** — профиль (`Profile`), память (`Memory`) и люди (`Person`): Go `model/personal.go` ↔ TS `domain/types.ts`,
    проверки — `domain/profile.ts` ↔ `api/profile.go`/`memory.go`/`people.go`. Память и карточки людей пишет только
    разбор реплики пользователя после ответа (`memory_extract.go`, см. `server/AGENTS.md`). Анкета знакомства открывается сама, пока `profile.onboarded` — false.
    **Предложения** (`Suggestion`, `api/suggestions.go`) считаются на сервере правилами без модели: ключ `key` не даёт
    повторов, лимит — `profile.proactive` в день, `profile.muted` выключает виды. Новое правило — функция в `planSuggestions`
    с тестом; «Да» выполняется на сервере (кроме `chat` — его запрос шлёт клиент). Массовые действия ассистента
    (`shift_events` больше трёх событий или на другой день, `clear_day` всегда) подтверждаются той же кнопкой, что и удаления.
15. **Повторяющиеся события** (`repeat`, `repeatUntil`, `exdates`): вхождения приходят с id серии и своей датой.
    Правка по id меняет серию; при правке вхождения передавайте `occurrence` (его день), «только этот день» — `skip`.
    Локальный режим повторяет правила сервера в `domain/repeat.ts`. Повтор есть только у своих событий (без `source`).

## React и TypeScript

- Строгий TS: `noUncheckedIndexedAccess`, `verbatimModuleSyntax`. Индексация массивов даёт
  `T | undefined` — обрабатывайте, не глушите `!`.
- Типы импортируются как `import type` / `type X` (ESLint `consistent-type-imports`).
- ESLint с правилами React Compiler (`react-hooks` recommended-latest) и `jsx-a11y`.
  **`eslint-disable` запрещены.** Если линтер ругается на эффект — правильный инструмент почти всегда:
  - колбэк из пропсов внутри эффекта → `useEffectEvent`;
  - таймеры → `useTimeout` / `useInterval` из `lib/hooks.ts` (сами снимаются при размонтировании);
  - «текущее время» → `useNow()`;
  - производное состояние → вычислять в рендере или сбрасывать через `key`, а не `setState` в эффекте;
  - DOM-измерения/прокрутка до отрисовки → `useLayoutEffect`.
- Контекст: `use(Context)` и `<Context value>` (React 19). Каждый контекст узкий и мемоизирован.
- Компонент > ~150 строк или с несколькими независимыми частями — разбейте на файлы в папке экрана.
- `key={index}` допустим только для статичных или только растущих списков.

## Стили и дизайн

- **CSS Modules** рядом с компонентом. Цвета, радиусы, тени, слои — **токены** из
  `src/styles/global.css` (`--ink`, `--ink-2`, `--surface`, `--r-xl`, `--shadow-md`, `--z-sheet`…).
  Новые цвета — сначала токен, и сразу для обеих тем: `--x: light-dark(светлая, тёмная)`.
- **Тёмная тема:** токены — `light-dark()`, тема выбирается `color-scheme` (система) или `data-theme`
  на `<html>` (выбор в настройках, `lib/theme.ts`, хранится на устройстве). В тёмной теме `--ink` и
  `--surface-ink` светлые: текст на них — `--ink-inverse`; на цветных заливках (значки, «сейчас») —
  `--on-accent`; на тёмных плашках (`--surface-dark`: тосты, подсказки) — `--on-dark`.
  Полупрозрачный фон от токена — `color-mix(in srgb, var(--bg) 75%, transparent)`.
  Проверяйте UI в обеих темах.
- Не используйте `!important` (единственное исключение — сброс анимаций под `prefers-reduced-motion`
  в `global.css`). Чтобы перебить стили примитива, повышайте специфичность
  (`.parent .child`) или добавьте проп в примитив.
- Контраст: основной текст ≥ 4.5:1 (`--ink-2` проверен), крупный второстепенный — `--ink-soft` (≥ 3:1).
- Зоны нажатия ≥ 44 px (`Pill small` = 40 px — минимум для второстепенных действий).
- Мобильная вёрстка первична: проверяйте 390×844 и 375×667 (iPhone SE). Учитывайте
  `--safe-top`/`--safe-bottom`/`--bar-h` — на десктопе они переопределяются рамкой телефона.
- Шрифт — Inter Variable (локально, только кириллица и латиница — `styles/fonts.css`); заголовки — классы
  `display`/`title`, `tnum` для цифр.
- Редко открываемые экраны и шторки — `React.lazy` + `Suspense` (чат, вход, шторки аккаунта):
  основной чанк должен оставаться лёгким.

## Анимации (framer-motion)

- Компоненты — `m.*` из framer-motion (не `motion.*`): приложение обёрнуто в `LazyMotion strict`,
  возможности анимаций грузятся отдельным чанком (`lib/motionFeatures.ts`). `motion.div` упадёт в рантайме.
- Пресеты — `lib/motion.ts` (`spring`, `softSpring`, `bouncy`, `screenVariants`, `itemVariants`).
- Бесконечные анимации отключайте при `useReducedMotion()`; `MotionConfig reducedMotion="user"`
  гасит только transform/layout, не opacity/цвет.
- Не анимируйте `filter: blur()` на множестве элементов (дорого на iOS) — только opacity/transform.
- framer-motion управляет `transform`: не центрируйте анимируемый элемент через
  `transform: translate(-50%)` в CSS — используйте `left:0; right:0; margin:auto; width:fit-content`.
- Дочерние компоненты `AnimatePresence mode="popLayout"` должны принимать `ref` и передавать его
  в корневой `motion`-элемент (React 19: `ref` — обычный проп).
- Для layout-анимаций задавайте `borderRadius` в `style`, чтобы скругления не искажались.

## Доступность

- Иконочные кнопки — `aria-label`; переключатели — `aria-pressed` / `role="switch"` / `radiogroup`.
- Скрытые панели — `inert` + `aria-hidden`. Шторки — `BottomSheet` (`aria-modal`, фокус, Escape).
- Живые статусы — `aria-live="polite"` или `role="status"`.

## PWA

- Конфигурация сборки, манифест, иконки и shortcuts — `vite.config.ts` (`VitePWA`, `injectManifest`);
  маршруты Workbox, runtime-кэш и Background Sync — `src/sw.ts`.
- В режиме `--mode single` плагина PWA нет: `virtual:pwa-register/react` подменяется
  `src/pwa/registerStub.ts`.
- Текущий маршрут NetworkFirst перехватывает **GET** с путём `/api/`, кроме `/api/health`;
  кэш `api` хранит до 200 ответов на 7 дней, таймаут ожидания сети — 4 секунды.
  Это широкий маршрут: перед добавлением GET оцените приватность и допустимость устаревшего ответа.
- В очередь попадают мутации событий/задач при сетевой ошибке (`ApiError.status === 0`), не любые ошибки API.
  Replay останавливается на сети, `5xx` и `401`; остальные `4xx` отбрасывают операцию,
  `404` у PATCH/DELETE считается выполненным. Сохраняйте это различие, особенно для `424` календарей.
- Повтор из страницы (`useOutboxSync`) работает на старте, по `online`, изменению очереди и таймеру 30 секунд.
  Он доступен и в dev. Service worker и его Background Sync проверяйте на обычной production-сборке.
  В Safari/Firefox опирайтесь на повтор из открытой страницы, а не на Background Sync.
- Push: service worker обязан показать уведомление на каждый push (иначе Chrome покажет своё, а Safari отзовёт подписку),
  поэтому «тихих» пушей для синхронизации нет. Подписка требует зарегистрированного worker: в `npm run dev` и
  однофайловой сборке её нет, проверяйте на `npm run build` + `npm run preview` или Go-сервере. iOS — только у PWA на экране «Домой».
- Иконки PNG генерируются из `public/icon.svg` (размеры 192, 512, maskable 512, apple-touch 180).

## Текущие ограничения, которые нельзя считать гарантиями

- **Смена аккаунта:** операции очереди помечены владельцем (`PendingOp.owner`, мета `owner` в IndexedDB),
  replay не отправляет чужие операции, а вход другого пользователя стирает их (`outbox.setOwner`).
  Адрес API в операции не хранится — очередь не изолирована между бэкендами. При изменении сессии
  или офлайна проверяйте «A создал офлайн → выход → вход B → сеть» регрессионным тестом.
- **Приватный кэш:** кэш `api` в `src/sw.ts` общий для аккаунтов; при смене пользователя его стирает
  `api/session.ts` (`caches.delete('api')`), но запрос, начатый до смены, может положить ответ уже после.
  Проверяйте тот же URL после смены аккаунта при обрыве/задержке сети.
- **Одновременный replay:** флаг `flushing` локален для экземпляра очереди; страница, другая вкладка
  и service worker имеют отдельные экземпляры. `dedupe` ищет совпадения полей, а не использует серверный
  ключ идемпотентности; не обещайте строго однократное создание.
- **Другой домен API:** страница использует `VITE_API_URL`, но worker вызывает `flush('')`.
  Фоновый replay на отдельный бэкенд нельзя считать поддержанным без отдельной проверки.
- **AI-удаления и переносы:** выполняются только по кнопке на карточке (`confirmations` в
  `server/internal/api/confirm.go`). Ждущие действия хранятся в памяти процесса (10 минут, до следующей реплики):
  после перезапуска или на другом процессе сервера карточка устаревает (410) — действие нужно попросить снова.
  Меняя это, сохраняйте тесты «слова не удаляют» и «чужой не подтвердит».
- **Уведомления:** доставка проверяется тестами с поддельным сервисом доставки и расшифровкой (Go), а в браузере —
  только подписка/UI и обработчики service worker; настоящую доставку через FCM/APNs CI не проверяет. Напоминания
  считаются опросом раз в `REMINDER_INTERVAL` с запасом 10 минут: пропущенные дольше (сервер лежал) не придут.
  Несколько процессов сервера не задублируют напоминание (отметка `ClaimReminder` атомарна), но каждое устройство
  получает уведомление и при открытом приложении. Worker шлёт запросы кнопок на свой origin (`VITE_API_URL` не поддержан).
- **Предложения и выводы ассистента:** «не чаще раза в 30 минут» (предложения) и «раз в сутки» (догадки) помнит процесс
  (`suggester`, `inferrer`); после перезапуска проход повторяется, а повторов не даёт уникальный ключ в хранилище.
  Несколько процессов сервера считают их независимо. В локальном режиме ни предложений, ни догадок нет.
- **Массовые действия ассистента** (`shift_events` больше трёх событий или на другой день, `clear_day`) подтверждаются
  той же кнопкой, что и удаления. Сдвиг времени тремя событиями за вызов проходит без кнопки, поэтому модель может
  сдвинуть день несколькими вызовами.
  Повторяющиеся, внешние и многодневные события они не двигают.
- **Выход на других устройствах** (и смена пароля) снимает push-подписки всех устройств аккаунта: подписка не привязана
  к сессии. Текущее устройство подписывается снова при сверке (`usePushDevice`).
- **Картинки в чате** работают, только если `LLM_MODEL` понимает изображения; отказ модели распознаётся по HTTP-статусу
  (400/413/415/422), а не по тексту ошибки.
- **Клиент KMP** не заменяет PWA: в нём нет push и напоминаний, голоса, картинок в чате, анкеты
  знакомства и многодневных событий; сборка iOS проверена только в проекте, не запуском. Удаление события и задачи
  там откладывается на 5 секунд («Вернуть»): при закрытии приложения за это время удаление не дойдёт до сервера.
  Офлайн-очередь KMP (`api/Outbox.kt`) повторяет правила сайта, но только для событий и задач, лежит в хранилище устройства
  и доигрывается при открытом приложении (раз в 30 с, при возврате в окно и когда сеть вернулась): Background Sync нет.
  Чтение без сети — из кэша последних ответов (`ReadCache`, до 60 записей), он стирается при выходе.
  Сессия хранится на устройстве, на Android HTTP разрешён только в debug-сборке. Зелёный CI ничего не говорит о `kmp/`.
- **PostgreSQL в CI:** в текущем `ci.yml` нет сервиса БД и `TEST_DATABASE_URL`;
  зелёные Go-тесты не доказывают прохождение PostgreSQL-сценариев.

## Как проверить свою работу (Definition of Done)

1. Для изменений фронтенда — `npm run check` и `npm run build`
   без предупреждений о размере чанков. Для однофайлового режима — `npm run build:single`.
2. Для изменений Go — из `server/`: `test -z "$(gofmt -l .)" && go vet ./... && go test -race ./...`.
   Просто `gofmt -l .` выводит список, но не завершает проверку ошибкой при неформатированных файлах.
3. Для изменений PostgreSQL — дополнительно `TEST_DATABASE_URL=… go test -race ./internal/store -run TestPostgres -count=1`
   из `server/` на одноразовой БД. Для Docker/поставки — сборка образа и проверка `/api/health`.
4. Для изменений `kmp/` — из `kmp/`: `./gradlew :shared:jvmTest :shared:compileKotlinWasmJs :androidApp:assembleDebug`
   (подробности и проверка в браузере/на телефоне — `kmp/AGENTS.md`). iOS собирается только на macOS.
5. **Визуальная проверка UI-изменений:** запустите `npm run dev` и откройте экран в браузере на
   390×844 (и 375×667, если менялась вёрстка). Пройдите сценарий руками или через Playwright.
   Консоль браузера без ошибок. Для серверного режима — `make api` + `npm run dev` (нужна регистрация),
   для Docker — `docker compose up --build` и сценарий на :8080.
6. Новая логика покрыта тестом (`domain/`, `lib/`, `api/` — `http`/`local`/`offline`/`outbox`, Go-хендлеры,
   хранилище, `llm`).
7. README обновлён, если поменялись команды, API или поведение для пользователя.
8. Для изменений только документации — форматирование Markdown, ссылки/пути и соответствие команд
   исходникам; тесты приложения и сборка не обязательны. В финальном отчёте перечислите реальные проверки
   и ограничения среды; пропущенные проверки не называйте успешными.

## Git

- Коммиты — на русском: заголовок до ~72 символов в повелительном/назывном стиле
  («Бронь сохраняется на сервере…»), затем пустая строка и тело списком по областям.
- Не коммитьте `dist/`, `dist-single/`, `server/data/`, `.env`, содержимое `server/web/dist/` (кроме README).
- CI (`.github/workflows/ci.yml`) выполняет typecheck, lint, Vitest, Prettier, `npx vite build`,
  проверку gofmt, `go vet`, `go test -race` и сборку Docker без публикации образа.
  Проверки браузера и PostgreSQL в workflow не настроены; сборки `kmp/` в CI тоже нет.
- `deploy.yml` публикует статическую версию на GitHub Pages при пуше в `main` или ручном запуске;
  это локальный режим, без Go/LLM и подключения внешних календарей.
- Перед коммитом выполните проверки по области изменения из Definition of Done.
  Не переписывайте историю опубликованных веток; push — в согласованную ветку, без force.

## Известные подводные камни

- **Docker Hub rate limit:** при ошибке 429 используйте зеркало:
  `--build-arg NODE_IMAGE=mirror.gcr.io/library/node:22-alpine --build-arg GO_IMAGE=mirror.gcr.io/library/golang:1.24-alpine`.
- **Сеть в песочнице с TLS-прокси:** `npm ci` внутри `docker build` падает на сертификате. Для локальной
  проверки соберите со своей CA во временной копии Dockerfile (не меняйте основной).
- Фото с `images.unsplash.com` могут быть недоступны — `SmartImage` показывает градиентную заглушку,
  это ожидаемо.
- Vite dev-сервер проксирует `/api` на `:8080`; без сервера в консоли будут 502 на `/api/health` —
  это ожидаемо: при первом запуске в auto-режиме приложение уйдёт в локальный режим,
  а после успешного подключения к серверу сохранит серверный режим (см. `api/connect.ts`).
- Service worker требует HTTPS или localhost. На обычном HTTP по LAN-IP нельзя считать PWA/Background Sync
  работоспособными; тестируйте worker через `npm run build` + `npm run preview` на localhost или HTTPS.
- Деплой на домашний сервер (rsync + `docker compose up -d --build`, порт из `APP_PORT`) описан в README;
  `.env` на сервере не трогайте — там `LLM_API_KEY`. Не выполняйте деплой без явной просьбы.
