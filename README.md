# AI Календарь — интерфейс

Мобильный интерфейс AI-календаря по мотивам видео-референса: календарь, день по слоям «Утро / День / Вечер» и ассистент, который одной фразой планирует завтрак с другом. Ассистент сам находит свободное окно, подбирает место рядом и бронирует столик по телефону.

Фронтенд — PWA на React; бэкенд — Go (`server/`); собираются в один Docker-образ. Сценарий ассистента (разбор запроса, звонок в ресторан) пока заскриптован, а события, брони и история чата хранятся на сервере.

## Запуск

### Docker (UI + бэкенд в одном контейнере)

```bash
docker compose up --build        # http://localhost:8080
# или
docker build -t ai-calendar .
docker run -p 8080:8080 -v ai-calendar-data:/data ai-calendar
```

Образ собирается в три стадии: Node собирает PWA, Go встраивает её в бинарник через `go:embed`, итоговый образ — distroless, около 17 МБ. Данные лежат в томе `/data` (`data.json`), есть `HEALTHCHECK`, сервер работает от непривилегированного пользователя.

| Переменная     | По умолчанию | Назначение                                                |
| -------------- | ------------ | --------------------------------------------------------- |
| `PORT`         | `8080`       | Порт HTTP                                                 |
| `DATA_DIR`     | `/data`      | Каталог с `data.json`; пустое значение — хранить в памяти |
| `STATIC_DIR`   | —            | Раздавать UI с диска вместо встроенного (для разработки)  |
| `CORS_ORIGINS` | —            | Источники через запятую, которым разрешён доступ к API    |

Если Docker Hub ограничивает скачивание, базовые образы можно взять из зеркала:
`--build-arg NODE_IMAGE=mirror.gcr.io/library/node:22-alpine --build-arg GO_IMAGE=mirror.gcr.io/library/golang:1.24-alpine`.

### Разработка

```bash
npm install
make api          # Go-сервер на :8080 (нужен Go 1.24+)
npm run dev       # UI на :5173, /api проксируется на :8080
```

Без запущенного сервера UI работает в **локальном режиме**: демо-данные и всё, что вы создали, хранятся в браузере (`localStorage`). Режим выбирается при запуске сам: если `/api/health` отвечает — данные с сервера. Если приложение уже работало с сервером и сеть пропала, оно остаётся в режиме сервера и показывает кэш. Явно: `VITE_API_MODE=local|server`, адрес бэкенда на другом домене — `VITE_API_URL`.

Сборка без Docker:

```bash
npm run build        # dist/ — PWA для хостинга (на GitHub Pages работает в локальном режиме)
npm run build:single # dist-single/index.html — всё в одном файле, без service worker
make web             # положить сборку в server/web/dist, затем: cd server && go build ./cmd/server
```

### Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` публикует статическую версию при пуше в `main`. Включите Pages: **Settings → Pages → Source: GitHub Actions**.

## Бэкенд (Go)

Только стандартная библиотека Go: `net/http` с маршрутами Go 1.22, `log/slog`, `embed`. Хранилище — JSON-файл с атомарной записью; интерфейс хранилища изолирован в `internal/store`, его можно заменить на БД.

| Метод и путь                      | Что делает                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------- |
| `GET /api/health`                 | Проверка живости и версия                                                    |
| `GET /api/events?date=2026-10-20` | События дня: расписание, брони, события пользователя                         |
| `POST /api/events`                | Новое событие `{date, title, start, end, badge?}` (минуты от 0:00)           |
| `DELETE /api/events/{id}`         | Удалить событие                                                              |
| `GET /api/month?year=&month=`     | Значки событий по дням месяца (месяц с 1)                                    |
| `GET /api/places`                 | Заведения рядом                                                              |
| `GET /api/places/{id}/reviews`    | Отзывы                                                                       |
| `GET /api/bookings`               | Брони, новые первыми                                                         |
| `POST /api/bookings`              | Бронь `{placeId, date, start, end, guests, invite}`; 409, если место закрыто |
| `DELETE /api/bookings/{id}`       | Отменить бронь (остаётся в истории со статусом `cancelled`)                  |
| `GET/POST /api/messages`          | История чата с ассистентом                                                   |

Ошибки — JSON `{"error": "понятный текст"}` с кодом 400/404/409/413. Тело запроса ограничено 64 КБ, неизвестные поля отклоняются. Всё, что не `/api/*`, — PWA: файлы с хешем кэшируются навсегда, `index.html`, `sw.js` и манифест — `no-cache`, неизвестные пути отдают `index.html`.

```bash
cd server && go test ./...
```

## PWA

- **Установка:** манифест с иконками (в том числе maskable), `standalone`, тема и фон без белой вспышки. На Android и в десктопном Chrome — кнопка «Установить» на главном экране, на iPhone — подсказка «Поделиться → На экран „Домой“».
- **Офлайн:** service worker (Workbox) кэширует оболочку приложения и шрифты. Ответы API сохраняются по схеме «сначала сеть, потом кэш», фото — «сначала кэш». Без сети показывается плашка, а данные берутся из кэша.
- **Обновления:** о новой версии сообщает уведомление «Обновить», перезагрузка — только по нажатию. Приложение проверяет обновления раз в час.
- **Быстрые действия** с иконки: «Новое событие», «Ассистент», «Календарь на месяц» (`?action=…`).

| Экран                   | Что есть                                                                                                                                                                                                                       | Как попасть                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| **Сегодня** (главный)   | Ссылка «Открыть день», плашка месяца, ближайшее событие («Подключиться», «Весь день»), «Скоро» (брони, статус приглашения), «Задачи и цели» (отметка, оценка звёздами, категории), подсказка про ассистента при первом запуске | Стартовый экран                                  |
| **Месяц**               | Год и месяц, стрелки и свайп между месяцами, выбор месяца, прошедшие дни приглушены, точки событий, погода                                                                                                                     | Плашка с датой                                   |
| **День**                | Слои «Утро / День / Вечер», по умолчанию открыта текущая часть суток, линия «сейчас», нажатие на пустое время создаёт событие; лента недели со стрелками, кнопка «Сегодня»; режимы «шкала / список»                            | «Открыть день», день в месяце, ближайшее событие |

| **Чат**                 | История диалога, «живая активность» со списком задач ассистента, категории → готовые запросы (вставляются сразу), растущее поле, диктовка                                                                                      | Кнопка «∞»                                       |
| **Голосовой ввод**      | Слова «распознаются» по одному, затем «Отправить» или «Исправить» — ничего не уходит без проверки                                                                                                                              | «Нажмите и говорите»                             |
| **Запрос**              | Запрос и распознанные параметры (день, гости, радиус, приглашение Глебу) — каждый можно поменять; автостарт через 4 с, останавливается при любой правке; «Изменить текст»                                                      | После отправки                                   |
| **Время**               | Свободное окно с соседними делами, другие окна, «Своё время» с проверкой пересечений                                                                                                                                           | «Искать»                                         |
| **Поиск ресторана**     | Радар, затем карусель: рейтинг, пешком, цена, открыто ли в нужное время (закрытые нельзя забронировать)                                                                                                                        | «Искать места на …»                              |
| **Подтверждение брони** | Место, время, число гостей, приглашение Глеба, какие данные уйдут ресторану                                                                                                                                                    | «Забронировать»                                  |
| **Подробнее / Отзывы**  | Шторка: факты, часы работы и цена, теги, отзывы                                                                                                                                                                                | «Подробнее» или «Отзывы»                         |
| **Бронирование**        | Звонок с таймером, «Слушать», расшифровка, «Прервать звонок»; после брони — адрес, номер, статус приглашения и «Отменить бронь»                                                                                                | «Позвонить и забронировать»                      |

После «Готово» бронь появляется в блоке «Скоро» на главном экране, в истории чата и в дне брони (с пометкой «Новое»).

## Стек

- **React 19 + TypeScript (strict, `noUncheckedIndexedAccess`) + Vite**;
- **framer-motion** — переходы экранов, layout-анимации, жесты; бесконечные анимации отключаются при «уменьшении движения»;
- **CSS Modules** и токены в `src/styles/global.css` (цвета, радиусы, тени, слои z-index);
- шрифт **Inter Variable** подключён локально, с кириллицей.

## Проверки

```bash
npm run typecheck   # tsc для приложения и конфигов
npm run lint        # ESLint: typescript-eslint, react-hooks (правила React Compiler), jsx-a11y
npm run test        # vitest: доменная логика, даты, склонения, редьюсер ассистента
npm run check       # всё вместе + prettier --check
```

Те же проверки запускаются в CI (`.github/workflows/ci.yml`) на каждый пуш и PR.

## Структура

```
src/
  api/                 источник данных: http (Go-сервер) и local (браузер), хуки TanStack Query
  pwa/                 service worker, установка, офлайн, быстрые действия
  app/                 состояние интерфейса: узкие контексты
    navigation.tsx     стек экранов
    calendar.tsx       выбранный день
    assistant.tsx      запрос, черновик, голос
    composer.tsx       шторка нового события
    bar.tsx            нижняя панель: экран рендерит <BarSlot> через портал
    providers.tsx
  domain/              чистая логика без React и моков
    types.ts           типы предметной области
    calendar.ts        части суток, слоты, свободные окна
    restaurants.ts     часы работы (в т. ч. после полуночи), ранжирование
    request.ts         параметры запроса ассистенту
  mocks/               демо-данные для локального режима и сценарий звонка
  lib/                 даты, склонения (Intl.PluralRules), хуки таймеров, анимационные пресеты
  components/          общие UI: кнопки, BottomSheet (Escape, фокус, inert фона), иконки, нижняя панель
  screens/
    home/              Home, NextEvent, BookedCard, TasksGrid, PrepCard
    month/             Month, MonthGrid, MonthPicker, WeatherCard, WeatherArt
    day/               Day, PartCard, EventCard, Agenda, WeekStrip, ModeToggle
    chat/              Chat, ChatComposer, TasksPill, DayPreview
    agent/             Agent, useAgentFlow (редьюсер сценария), AgentBar, StepStack, шаги и шторки
server/
  cmd/server           точка входа: конфигурация из окружения, graceful shutdown, -healthcheck
  internal/api         маршруты, валидация, middleware (логи, recover, CORS, заголовки), раздача SPA
  internal/store       хранилище (JSON-файл)
  internal/seed        заведения, отзывы, типовое расписание
  internal/model       типы API
  web                  go:embed собранного UI
```
