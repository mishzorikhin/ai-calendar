# AI Календарь — интерфейс

Мобильный интерфейс AI-календаря по мотивам видео-референса: календарь, день по слоям «Утро / День / Вечер» и чат с ассистентом: LLM отвечает стримом, а через инструменты смотрит расписание, ищет свободное окно и добавляет события в календарь.

Приложение многопользовательское: регистрация и вход по логину и паролю, данные каждого привязаны к его аккаунту, задачи можно делить с другими — по `@логину` в названии или через список участников; события и чат остаются личными.

Можно подключить внешние календари — Google, Outlook, Яндекс, iCloud, Nextcloud или любую ссылку `.ics`: их события появляются рядом со своими, ассистент учитывает их при поиске времени, а новые события и правки уходят обратно в выбранный календарь. И наоборот — личная ссылка `.ics` показывает события приложения в Google, Apple или Outlook (см. «Внешние календари»).

Фронтенд — PWA на React; бэкенд — Go (`server/`); собираются в один Docker-образ. Ассистент — LLM с function calling (OpenAI-совместимый API, SSE-стриминг); события и история чата хранятся на сервере.

## Запуск

### Docker (UI + бэкенд в одном контейнере)

```bash
docker compose up --build        # http://localhost:8080
# или
docker build -t ai-calendar .
docker run -p 8080:8080 -v ai-calendar-data:/data ai-calendar
```

Образ собирается в три стадии: Node собирает PWA, Go встраивает её в бинарник через `go:embed`, итоговый образ — distroless, около 17 МБ. Есть `HEALTHCHECK`, сервер работает от непривилегированного пользователя.

`docker compose up --build` поднимает два сервиса: приложение и PostgreSQL 17 (образ `postgres:17-alpine`). Данные лежат в томе `db-data`; старый `data.json` из тома `data` при первом запуске импортируется в базу однократно. Пароль базы задаётся `DB_PASSWORD` (по умолчанию `calendar`).

### Деплой на сервер

Продакшен-копия живёт на домашнем сервере `192.168.0.16` (SSH: `root`, ключ `~/.ssh/id_ed25519`), проект — в `/opt/ai-calendar`, UI — на `http://192.168.0.16:8090`. Снаружи приложение доступно по `https://aicall.mish-tech.ru/` — обратный прокси с TLS к тому же контейнеру.

Важно: push-уведомления и service worker работают только по HTTPS-адресу — по `http://192.168.0.16:8090` браузер считает origin небезопасным (`isSecureContext === false`), `navigator.serviceWorker` недоступен, и подписаться на уведомления нельзя. Это ограничение браузеров, а не сервера. Обновление:

```bash
# исходники → сервер (.env сервера не трогаем: там LLM_API_KEY и APP_PORT)
rsync -az --delete \
  --exclude node_modules --exclude .git --exclude .github --exclude .env \
  --exclude dist --exclude dist-single --exclude server/data \
  --exclude server/web/dist --exclude '*.log' \
  ./ root@192.168.0.16:/opt/ai-calendar/

ssh root@192.168.0.16 'cd /opt/ai-calendar && docker compose up -d --build'

# проверка
curl http://192.168.0.16:8090/api/health
TOK=$(curl -s -X POST http://192.168.0.16:8090/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"...","password":"..."}' | jq -r .token)
curl -N -X POST http://192.168.0.16:8090/api/chat -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' -d '{"text":"привет"}'

# push: ключ VAPID и число подписанных устройств
curl -s http://192.168.0.16:8090/api/push -H "Authorization: Bearer $TOK"
# тестовое уведомление на все устройства аккаунта (409 — ни одно не подписано)
curl -X POST http://192.168.0.16:8090/api/push/test -H "Authorization: Bearer $TOK"
```

Нюансы: порт хоста задаёт `APP_PORT` в `.env` — там `8090`, потому что `8080` занят llama.cpp; данные — в PostgreSQL (`db-data`), пересборка их не трогает; `--delete` убирает удалённые из репозитория файлы, исключённые пути сохраняются.

### Разработка

```bash
npm install
make api          # Go-сервер на :8080 (нужен Go 1.24+)
npm run dev       # UI на :5173, /api проксируется на :8080
```

Без запущенного сервера UI работает в **локальном режиме**: демо-данные и всё, что вы создали, хранятся в браузере (`localStorage`) — аккаунт там не нужен. Режим выбирается при запуске сам: если `/api/health` отвечает — данные с сервера и приложение просит войти; токен сессии хранится в браузере, уходит в каждом запросе и сбрасывается по `401`. Если приложение уже работало с сервером и сеть пропала, оно остаётся в режиме сервера и показывает кэш, а правки событий и задач ждут в офлайн-очереди (см. раздел PWA). Явно: `VITE_API_MODE=local|server`, адрес бэкенда на другом домене — `VITE_API_URL`.

Сборка без Docker:

```bash
npm run build        # dist/ — PWA для хостинга (на GitHub Pages работает в локальном режиме)
npm run build:single # dist-single/index.html — всё в одном файле, без service worker
make web             # положить сборку в server/web/dist, затем: cd server && go build ./cmd/server
```

### Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` публикует статическую версию при пуше в `main`. Включите Pages: **Settings → Pages → Source: GitHub Actions**.

## Бэкенд (Go)

Только стандартная библиотека Go: `net/http` с маршрутами Go 1.22, `log/slog`, `embed`; для PostgreSQL — `pgx/v5`. Хранилище изолировано интерфейсом в `internal/store`: по умолчанию JSON-файл с атомарной записью, при заданном `DATABASE_URL` — PostgreSQL (таблицы `users`, `sessions`, `events`, `messages`, `tasks`, `task_members`, `notifications` создаются миграцией, старый `data.json` импортируется однократно).

**Аккаунты и сессии.** Регистрация и вход по логину (латиница, `@логин`) и паролю; пароль хранится как PBKDF2-SHA256-хэш (stdlib `crypto/pbkdf2`), сессия — Bearer-токен сроком 30 дней со скользящим продлением, в базе лежит его sha256. Все маршруты данных требуют `Authorization: Bearer <token>`; пользователь попадает в контекст запроса через middleware, и хранилище фильтрует записи по нему. Данные до-аккаунтной эпохи (без владельца) усыновляет первый зарегистрированный пользователь.

**Совместные задачи.** Задачу видят владелец и участники (`task_members`), обе стороны могут править поля. Поделиться можно двумя способами: `@логин` в названии или заметке (парсится сервером при создании и правке) и явный список `members` / маршрут участников. Участник получает уведомление, может выйти сам; владелец удаляет задачу у всех и снимает любых участников. События и история чата — всегда личные.

Как работают упоминания:

- Задачу делит только **новое** упоминание — которого не было в тексте до правки. Повторные сохранения не шлют уведомления снова, а того, кто вышел или кого убрал владелец, старое упоминание обратно не возвращает. Стёрли `@логин` и написали заново — это новое приглашение.
- Упоминание начинается после пробела, начала строки или знака препинания: в «misha@bob.ru» и «иван@bob» упоминания нет. Точка, дефис или подчёркивание в конце («с @bob.») к логину не относятся, если такого логина нет.
- Неизвестный `@логин` — просто текст. Упомянуть себя или владельца можно: участником они не становятся и ошибки нет. Явно добавить владельца через `members` — ошибка 400.
- У упомянутого общая задача появляется без перезагрузки: приложение раз в минуту проверяет уведомления и при новом перечитывает задачи.

Ошибки — JSON `{"error": "понятный текст"}` с кодом 400/401/403/404/409/413/424/429 (424 — внешний календарь не принял изменение, 429 — превышен лимит, в ответе `Retry-After`). Лимиты: вход — 10 попыток в один аккаунт с одного адреса (дальше одна в 30 с; с другого адреса хозяин входит как обычно) и 30 с одного адреса, регистрация — 20 с адреса, чат — 10 сообщений подряд (дальше одно в 6 с); одновременных PBKDF2 — не больше четырёх. Тело запроса ограничено 64 КБ, неизвестные поля отклоняются. Название — до 120 символов, подзаголовок — до 200, сообщение — до 2000 (в локальном режиме те же ограничения). Если запись `data.json` не удалась, изменение откатывается. Сервер отдаёт `Content-Security-Policy` (всё своё, картинки — по HTTPS). Всё, что не `/api/*`, — PWA: файлы с хешем кэшируются навсегда, `index.html`, `sw.js` и манифест — `no-cache`, неизвестные пути отдают `index.html`.

Ассистент — цикл инструментов поверх чат-комплита: модель может вызвать `get_day_schedule`, `find_free_slots`, `create_event`, `update_event`, `delete_event`, `list_tasks`, `create_task`, `update_task`, `delete_task`, а для совместной работы — `list_users` (логины пользователей) и параметр `members` в задачных инструментах. Удаление и массовый перенос выполняет только кнопка: вызов `delete_event`/`delete_task`/`clear_day` (и `shift_events` больше трёх событий или на другой день) ничего не меняет — модель получает `needs_confirmation`, а под ответом появляется карточка «Удалить «…»? · Удалить / Не надо». Сервер выполняет запомненный вызов по `POST /api/chat/confirms/{id}` и пишет итог в историю; если событие за это время изменилось, ничего не делает. Карточка живёт до следующей реплики и не дольше 10 минут. Слова в чате ничего не подтверждают, поэтому команда «удали» в тексте чужого события не сработает. Тексты событий и задач промпт велит считать данными, а не указаниями. В промпте — дата и время в поясе пользователя; `find_free_slots` на сегодня не предлагает прошедшее время. Последний из шести заходов идёт без инструментов, чтобы модель ответила текстом. Ответ стримится по токенам, параллельные вызовы инструментов собираются по `index`; если провайдер не принял `stream` (400/404/422…), запрос повторяется обычным, а 401/429/5xx не повторяются. Если модель оборвалась посреди ответа, начало сохраняется в истории, а поток шлёт `error`. Ответ не зависит от соединения: если закрыть чат, сервер допишет его (до 5 минут) и сохранит.

Блок «Задачи и цели» на главном хранится в таблице `tasks` (в Postgres — создаётся миграцией). Цели (`kind=goal`) показываются большими карточками с отметкой и дедлайном, задачи (`kind=task`) — строками с сегментом категории и чекбоксом; общие задачи помечаются аватарками участников.

## Внешние календари

Шторка «Календари» открывается из аккаунта (аватар на главном). Всё работает только в режиме сервера.

| Как подключить                 | Направление   | Что нужно                                                                                   |
| ------------------------------ | ------------- | ------------------------------------------------------------------------------------------- |
| **Google Календарь**           | в обе         | Кнопка «Google Календарь» — вход через Google (нужно OAuth-приложение на сервере, см. ниже) |
| **Outlook / Microsoft 365**    | в обе         | Кнопка «Outlook» — вход через Microsoft (OAuth-приложение на сервере)                       |
| **Яндекс, iCloud, Nextcloud…** | в обе         | CalDAV: логин и **пароль приложения** (Яндекс ID → Безопасность; account.apple.com)         |
| **Любая ссылка `.ics`**        | только чтение | Праздники, расписание команды, «Секретный адрес в формате iCal» из Google без OAuth         |
| **Наш календарь в других**     | наружу        | «Создать ссылку» → вставить в Google («Другие календари» → «По URL»), Apple или Outlook     |

Как это устроено:

- События внешних календарей хранятся вместе со своими (`source` — id подключения), поэтому день, месяц, «Далее» и инструменты ассистента (`get_day_schedule`, `find_free_slots`) видят их без отдельной логики. События на весь день показываются полосой над шкалой и время не занимают.
- Синхронизация — окно «−30 … +365 дней» вокруг сегодня: при подключении, по кнопке «Обновить» и в фоне раз в `CALENDAR_SYNC_INTERVAL`. Повторы (`RRULE`, `EXDATE`, перенесённые и отменённые вхождения) разворачиваются на сервере; Google и Microsoft разворачивают их сами.
- Календарь с отметкой «Новые события — сюда» получает события, созданные в приложении и ассистентом. Правки и удаления событий из Google/Outlook/CalDAV сначала уходят туда (CalDAV — с проверкой версии `If-Match`, чужие свойства вроде напоминаний сохраняются). Если сервис недоступен, новое событие сохраняется в приложении, а ошибка видна в настройках календаря.
- Только для чтения: подписки `.ics`, вхождения повторяющихся серий CalDAV, события на весь день и многодневные (они режутся по дням).
- Время переводится в пояс пользователя: браузер сам сообщает его серверу (`PATCH /api/me {timeZone}`).
- Пароли CalDAV и OAuth-токены хранятся зашифрованными (AES-256-GCM, ключ `SECRET_KEY` или `DATA_DIR/secret.key`). Смена ключа — календари с паролем придётся подключить заново.
- Сервер не ходит по адресам внутренней сети (loopback, 10/8, 192.168/16 и т. п.) — пользователь вводит адреса сам. Свой Nextcloud дома — `CALENDAR_ALLOW_PRIVATE=1`.

**Google.** В [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите Google Calendar API, на странице OAuth consent screen добавьте область `…/auth/calendar.events`, затем Credentials → OAuth client ID → Web application с адресом возврата `PUBLIC_URL/api/integrations/oauth/google/callback`. Google требует HTTPS-домен (кроме `localhost`), поэтому на сервере по IP-адресу вход через Google не заработает — там используйте ссылку `.ics`. Пока приложение в режиме «Testing», войти могут только добавленные тестовые пользователи, а доступ живёт 7 дней.

**Microsoft.** В [Entra ID → App registrations](https://entra.microsoft.com/) зарегистрируйте приложение для «любых учётных записей Microsoft», платформа Web с адресом возврата `PUBLIC_URL/api/integrations/oauth/outlook/callback`, разрешения Microsoft Graph `Calendars.ReadWrite` и `offline_access`, создайте секрет клиента.

## Уведомления и напоминания

Пуш-уведомления о встречах, сроках задач, план на день и уведомления о совместных задачах. Шлёт их свой сервер по стандарту Web Push — без Firebase, аккаунтов разработчика и ключей сторонних сервисов.

- **Ключ.** Сервер сам создаёт пару ключей VAPID (P-256) при первом запуске и хранит закрытый ключ в хранилище (PostgreSQL или `data.json`) — попадает в те же бэкапы. Можно задать свой в `VAPID_PRIVATE_KEY`. Если ключ сменить или потерять, уведомления перестанут приходить на все устройства, пока их не включат заново.
- **Доставка.** Адрес подписки выдаёт браузер: Chrome — Google FCM, Firefox — Mozilla, Safari — Apple. Регистрироваться там не нужно, а содержимое шифруется для устройства (RFC 8291) — сервис доставки видит только зашифрованные байты, размер и время. Реализация — `server/internal/webpush`, только стандартная библиотека Go.
- **Где работает.** Android и компьютер — в любом современном браузере и в установленном приложении. iPhone и iPad (iOS 16.4+) — только у приложения, добавленного на экран «Домой». Нужен HTTPS (или `localhost`). В режиме разработки (`npm run dev`) service worker не регистрируется — проверяйте на сборке. В режиме инкогнито Chrome push не поддерживает.
- **Включение.** Аккаунт → «Напоминания» → «Уведомления на этом устройстве». Разрешение браузер спрашивает только по нажатию. Кнопка «Проверить» присылает пробное уведомление. При выходе из аккаунта подписка устройства снимается; если на устройстве вошёл другой человек, чужая подписка не переходит к нему.
- **Что приходит.** О встречах — за выбранное время до начала (по умолчанию за 10 минут; у каждого события можно выбрать своё в шторке события, в том числе у событий подключённых календарей, — во внешний календарь это не уходит). О задачах и целях — в день срока в выбранное время, пока не отмечены. План на день — утром, если в дне что-то есть. О совместной задаче — когда с вами поделились.
- **Вибрация.** На Android уведомления вибрируют: встреча — тремя импульсами, задача — двумя, сводка — коротко; отложенное или обновлённое уведомление вибрирует снова. iPhone вибрирует по системным настройкам «Звуки и тактильные сигналы» — рисунок там задать нельзя. Встреча «сейчас» на компьютере висит, пока её не закроют.
- **Кнопки.** У встречи — «Через 10 минут», у задачи — «Готово» и «Через час» (Android и десктоп; iOS кнопки не показывает). Нажатие на уведомление открывает нужный день.
- **Как считается.** Раз в `REMINDER_INTERVAL` сервер смотрит события и задачи пользователей с подписанными устройствами и отправляет то, чему пришло время (с запасом 10 минут на перезапуск). Отдельной очереди заданий нет — напоминания вычисляются из текущих данных, так что перенос встречи (в том числе ассистентом или синхронизацией календаря) сразу переносит и напоминание. Повторы отсекает отметка в хранилище. Время — в поясе пользователя, переход на летнее время учтён.
- **Лента `.ics`.** В личную ленту попадают напоминания `VALARM` — штатный календарь телефона может напоминать и сам. iOS по умолчанию убирает напоминания у календарей по подписке — их можно включить в настройках подписки.
- **Свои напоминания без события.** «Позвонить маме в 18:00» — в шторке «Напоминания» (текст и «Через час», «Завтра в 9:00», точное время) или ассистенту («напомни через 20 минут» — инструмент `create_reminder`). Там же список ещё не пришедших, их можно отменить.
- **Тихие часы.** Например, 23:00–7:00: в это время приходят только напоминания, заданные явно (своё у события, свои напоминания, «Отложить»), а напоминания по умолчанию, о задачах, сводки и уведомления о совместных задачах — нет (последние остаются в шторке аккаунта).
- **План на завтра** вечером и **просроченные задачи** в утренней сводке. **Своё время для типов событий** — например, спорт за час, работа — без напоминаний.
- **Число на иконке.** Сколько встреч ещё впереди сегодня и незакрытых задач со сроком сегодня или раньше: обновляется приложением и каждым push (Badging API — PWA на iPhone и Chrome на компьютере).
- **Открытое приложение.** Если оно на экране, в Chrome, Edge и других браузерах на Chromium вместо системного уведомления приходит плашка в нём (с вибрацией на Android и кнопкой «Готово» у задачи). В Safari, на iPhone и в Firefox системное показывается всегда — без него они отзывают подписку или урезают квоту.
- **Общие задачи.** Участники узнают, когда задачу отметили выполненной, вернули в работу или перенесли срок (правки текста не сообщаются).
- **Устройства.** Список устройств с уведомлениями («Chrome · Android») — старое можно отключить.
- Ассистент умеет «напомни за час» — параметр `reminders` в `create_event`/`update_event`.

## Персонализация ассистента

Ассистент подстраивается под человека — тремя слоями:

- **Профиль** («Ассистент обо мне» в настройках, анкета при первом входе): подъём и отбой, рабочие часы и дни, когда
  лучше думается, обычная длина встречи и перерыв между делами, «святые» блоки (обед, спорт, дорога), «на ты/на вы»,
  коротко или подробно, свободный текст «о себе». Окна для дел ищутся только в этих границах.
- **Память** («Что ассистент знает»): факты из разговоров — «зовут Миша», «живёт в Казани», «по пятницам не работаю»,
  «у мамы день рождения 14 марта». Устроена как у ChatGPT и Claude: после каждого ответа сервер отдельным коротким
  запросом к модели (`LLM_MEMORY_MODEL`, по умолчанию та же модель) разбирает реплику пользователя и решает, что
  добавить, обновить или забыть; под ответом появляется «Запомнил: …» — нажатие открывает список. Пометку шлёт сервер
  после настоящей записи, поэтому «запомнил» на словах модели не бывает. В разбор попадают только слова пользователя
  (и прошлая реплика ассистента как контекст вопроса) — текст из чужого события в память не попадёт. На прямую просьбу
  «запомни …» работает тем же путём. В промпт идут все факты (сначала «о себе», правила и предпочтения, ближайшие даты,
  затем свежие; если не влезли — модель дочитает список сама). Память выключается одним переключателем — тогда ничего
  не сохраняется и не уходит модели.
- **Люди**: карточки «кто это, где обычно видимся, сколько длится встреча, день рождения». Их ведёт тот же разбор
  («Глеб — мой коллега, видимся в кофейне»), а в промпт идут все карточки.

Всё это видно и правится в приложении; в локальном режиме профиль, факты и люди хранятся в браузере.

**Неделя и привычки.** Кнопка «Неделя» в карточке «Сегодня» — сколько времени ушло на встречи по дням и типам, сколько
осталось для сосредоточенной работы (свободные окна от полутора часов) и сколько задач закрыто, в сравнении с обычной неделей.
Привычка — третий вид задачи: каждый день, по будням или раз в неделю; на главной карточка с серией и точками недели, отметка
одним нажатием (и офлайн). В `PATCH /api/tasks/{id}` — `{check|uncheck: "ГГГГ-ММ-ДД"}`, `cadence`; закрытие ставит `doneAt`.

**Аккаунт.** В «Безопасность и данные»: смена пароля (остальные устройства выходят), список устройств со входом
и выход на любом из них, «Скачать мои данные» (JSON) и удаление аккаунта с паролем и двойным подтверждением.

**Планирование.** «Разложи задачи на сегодня» — ассистент предлагает план по свободным окнам (сначала фокус-время,
с учётом сроков и оценки «Сколько займёт» у задачи) и только после согласия ставит события, связанные с задачей: в шторке
такого события задачу можно сразу отметить выполненной. «Сдвинь всё после обеда на час», «освободи пятницу» — массовый
перенос; больше трёх событий, перенос на другой день и освобождение дня — только по кнопке под ответом.

**Картинки.** В поле чата есть кнопка фото: скриншот письма, афиша, расписание — ассистент найдёт даты и время и
предложит событие. Картинка сжимается в браузере (до 1600 px и 1,5 МБ), в истории остаётся пометка «📎 фото». Нужна модель
со зрением (`LLM_MODEL`); если сервис модели отклонил запрос с картинкой, ассистент так и скажет и предложит описать её словами.

**Выводы из поведения.** Раз в сутки сервер смотрит на свои события за 60 дней и задачи и делает догадки: «Обычно спорт
длится 1,5 ч», «Спорт — обычно вт, чт вечером», «задачу переносили уже 3 раза». Догадки появляются в «Что ассистент знает»
с вопросом «верно?» и не уходят модели, пока их не подтвердить; отклонённая не предлагается снова. Подтверждённая
длительность становится длительностью по умолчанию для этого типа в редакторе события.

**Предложения.** Ассистент и сам замечает, что можно улучшить, — и предлагает карточкой на главной и push с кнопками
«Да»/«Нет»: занять последнее окно под обед в плотный день, поставить час на просроченную или давно открытую задачу,
напомнить заранее о дне рождения или дате из памяти, разложить задачи по свободным окнам, разобрать перегруженную неделю.
Правила простые и без вызова модели; не больше `proactive` предложений в день (0–3, в «Ассистент обо мне»), не в тихие
часы, одно и то же не повторяется. «Не предлагать» выключает такой вид. В локальном режиме предложений нет.

## События на весь день

В шторке события длительность «Весь день»: отпуск, переезд, день рождения (вместе с «Каждый год»). Такое событие время не занимает и лежит полосой над шкалой — как праздники из подключённых календарей. Напоминание о нём приходит в плане на день, в ленту `.ics` оно уходит датой (`VALUE=DATE`). Как и серии, во внешний календарь оно не пишется. Ассистенту — `all_day` в `create_event`.

## Подробности события и несколько дней

В шторке события — «Место» (с кнопкой «На карте») и раздел «Подробнее»: ссылка на созвон или билет, заметки, дорога до
места и «несколько дней». Дорога занимает время перед началом (на шкале — пунктир «в пути»), окна ассистента её учитывают,
а в момент выезда приходит «Пора выезжать». Многодневное событие (конференция, поездка, отпуск) лежит одной записью и
показывается в каждом дне: первый — с начала до полуночи, последний — с полуночи до конца, средние — полосой «весь день»;
напоминание — только в первый день, в ленту `.ics` — одним событием. У событий подключённых календарей описание и ссылка
на созвон (Google Meet, Teams, Zoom, Телемост) подтягиваются сами — в шторке есть «Подключиться».

## Участники встреч

В шторке события (с сервером) — «Пригласить»: пользователи сервера по `@логину`, ассистенту — `attendees`. Приглашённому
приходят уведомление и push, встреча появляется в его календаре пунктиром «Приглашение · от …» с кнопками «Приду» /
«Не приду»; владелец видит ответы и узнаёт о них уведомлением. Перенос и отмена встречи приходят тем, кто не отказался,
отказ убирает встречу из дня приглашённого. Изменить чужую встречу нельзя, а в его ленту `.ics` она не попадает.

## Повторяющиеся события

«Каждый вторник йога», «планёрка по будням»: в шторке события — «Повтор» (каждый день, по будням, каждую неделю, каждый месяц, каждый год), ассистенту — параметр `repeat`. В базе одна запись, а день, месяц, свободные окна, напоминания и лента `.ics` получают вхождения с тем же id и своей датой. Правка вхождения меняет всю серию (перенос дня сдвигает серию целиком); удалить можно «только этот день» или всю серию. 31-е число и 29 февраля повторяются только там, где такой день есть. Повторы — только у событий приложения: во внешний календарь серия не уходит.

## PWA

- **Установка:** манифест с иконками (в том числе maskable), `standalone`, тема и фон без белой вспышки. На Android и в десктопном Chrome — кнопка «Установить» на главном экране, на iPhone — подсказка «Поделиться → На экран „Домой“».
- **Офлайн:** собственный service worker (`src/sw.ts`, Workbox-модули через `injectManifest`) кэширует оболочку приложения и шрифты. Ответы API сохраняются по схеме «сначала сеть, потом кэш», фото — «сначала кэш». Без сети показывается плашка со счётчиком ожидающих изменений, а данные берутся из кэша.
- **Очередь изменений:** мутации событий и задач при обрыве сети складываются в `outbox` (IndexedDB: операции, карта временных id → серверных, метаданные) и поверх чтений показываются как уже применённые — офлайн-созданное переживает перезапуск. Очередь доигрывается по Background Sync даже с закрытым приложением (Chromium/Android); где Sync API нет (Safari, Firefox), её выгоняет страница — на старте, по событию `online` и по таймеру. Повторные правки одной сущности сливаются, удаление неотправленного create отменяет его (правка или удаление во время отправки create встают следом отдельной операцией). Очередь помнит владельца: каждая операция помечена автором и уходит только с его сессией; вход другого пользователя стирает чужие операции, а выход и повторный вход того же — нет. Кэш ответов API в service worker общий для аккаунтов, поэтому при выходе и смене пользователя он стирается. Чат-стрим в очередь не кладётся — у него свой UI ошибки и повтора.
- **Авторизация офлайн:** токен сессии дублируется из `localStorage` в метаданные очереди — у service worker нет доступа к `localStorage`, а replay идёт с `Authorization: Bearer`. Ответ `401` останавливает обход, не теряя операций, — до свежего входа.
- **Обновления:** о новой версии сообщает уведомление «Обновить», перезагрузка — только по нажатию. Приложение проверяет обновления раз в час.
- **Уведомления:** service worker показывает push от своего сервера, обрабатывает кнопки «Готово» и «Отложить» (запросы — с токеном из метаданных очереди) и переподписывается, если браузер сменил подписку (`pushsubscriptionchange`). Подробнее — «Уведомления и напоминания».
- **Быстрые действия** с иконки: «Новое событие», «Ассистент», «Задача голосом», «Календарь на месяц» (`?action=…`).

## Стек

- **React 19 + TypeScript (strict, `noUncheckedIndexedAccess`) + Vite**;
- **framer-motion** — переходы экранов, layout-анимации, жесты; бесконечные анимации отключаются при «уменьшении движения»;
- **CSS Modules** и токены в `src/styles/global.css` (цвета, радиусы, тени, слои z-index);
- шрифт **Inter Variable** подключён локально, с кириллицей.

## Проверки

```bash
npm run typecheck   # tsc для приложения и конфигов
npm run lint        # ESLint: typescript-eslint, react-hooks (правила React Compiler), jsx-a11y
npm run test        # vitest: доменная логика, даты, склонения, API-клиенты, офлайн-очередь
npm run check       # всё вместе + prettier --check

cd server && gofmt -l . && go vet ./... && go test -race ./...
# хранилище на настоящем PostgreSQL (нужна пустая тестовая база):
TEST_DATABASE_URL=postgres://... go test ./internal/store -run TestPostgres
```

Внешние сервисы в тестах не нужны: CalDAV, Google и Microsoft подменяются поддельными серверами из `server/internal/calsync/fakecal`.

Те же проверки и сборка Docker запускаются в CI (`.github/workflows/ci.yml`) на каждый пуш и PR.
