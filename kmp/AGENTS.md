# kmp/AGENTS.md — клиент на Kotlin Multiplatform

Правила для агентов, работающих в `kmp/`. Общие правила (язык, Git, документация) — в корневом
[AGENTS.md](../AGENTS.md); человеческое описание и запуск — в [README.md](README.md); план переноса экранов и
его статус — в [PLAN.md](PLAN.md); чек-лист ревью — в [REVIEW.md](../REVIEW.md).

Клиент рисует те же экраны, что веб-PWA на React, но нативно: Android, iOS и веб (Wasm, запасной JS). Сервер — тот же
Go-бэкенд. **Эталон внешнего вида — веб:** https://aicall.mish-tech.ru/ и `src/screens` с `*.module.css`. Не придумывайте
второй интерфейс: перед правкой экрана откройте его на сайте и в tsx/CSS, сверяйте размеры, а не «похоже».

## Стек и модули

- Kotlin 2.4, Compose Multiplatform 1.11 (Material 3 только как основа, внешний вид — свой), Ktor 3.5 (клиент),
  kotlinx-serialization / -datetime / -coroutines. Версии — `gradle/libs.versions.toml`.
- `shared/` — весь код приложения (`commonMain`), тесты (`commonTest`) и тонкие `expect/actual` под платформы
  (`androidMain`, `iosMain`, `jvmMain`, `webMain`: хранилище настроек, HTTP-движок, открытие ссылки, тема, системные панели).
- `androidApp/`, `iosApp/`, `webApp/` — оболочки запуска. В `androidApp/src/debug` лежит манифест, разрешающий HTTP
  (только отладка); релиз ходит по HTTPS.
- Цели iOS собираются только на macOS с Xcode. На Linux проверяются JVM, JS, Wasm и Android.

## Команды (из `kmp/`)

| Задача                                      | Команда                                                  |
| ------------------------------------------- | -------------------------------------------------------- |
| Тесты общей логики                          | `./gradlew :shared:jvmTest`                              |
| Быстрая проверка компиляции Wasm и JS       | `./gradlew :shared:compileKotlinWasmJs :shared:compileKotlinJs` |
| Веб (dev, http://localhost:8088)            | `./gradlew :webApp:wasmJsBrowserDevelopmentRun`          |
| Веб для выкладки / проверки в браузере      | `./gradlew :webApp:wasmJsBrowserDistribution` → `webApp/build/dist/wasmJs/productionExecutable` |
| Android (APK в `androidApp/build/outputs/apk/debug/`) | `./gradlew :androidApp:assembleDebug`           |
| Установить на телефон                       | `adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk` |

- Первая сборка требует сети (зависимости Gradle): `--offline` падает с «No cached version…».
- `kmp/local.properties` с `sdk.dir` нужен для Android и не коммитится.
- Для веба сервер должен разрешить источник страницы: `CORS_ORIGINS=http://localhost:8088`.
- CI (`.github/workflows/ci.yml`, Java 21) запускает `:shared:jvmTest`, `:shared:compileKotlinWasmJs`
  и `:androidApp:assembleDebug`. JS, production-сборка веба, iOS и сценарии на устройстве требуют отдельных проверок.

## Архитектурные правила

1. **Сеть — только `CalendarApi`.** Экраны не обращаются к Ktor и не знают адресов. Новый эндпоинт = метод в
   `CalendarApi` + DTO в `Models.kt` + действие в `CalendarController`, а не локальное состояние вместо сервера.
2. **Состояние — в `CalendarController`.** Экран читает поля и вызывает методы; запросы идут через
   `guard { … }` (счётчик загрузки, ошибка, выход при `401`). Устаревшие ответы отбрасывайте (`dayWanted`,
   `searchSeq`, ключ месяца).
3. **Контракт в двух местах:** Go `server/internal/model` ↔ `api/Models.kt`. Меняете поле — меняйте обе стороны и
   тесты. Лимиты длин и проверки — как в `src/domain/limits.ts` и `server/internal/api`. Месяц в `/api/month` — с 1;
   даты в API — `ГГГГ-ММ-ДД` (`isoDate` / `parseIsoDate`), время внутри дня — минуты от полуночи.
4. **Сессия:** токен и адрес — `SessionStore` (`SharedPreferences`/`UserDefaults`/`localStorage`). Не логируйте токен,
   не дублируйте его. HTTP принимается только для localhost и частных адресов (`normalizeUrl`, `isLocalHost`).
   При смене аккаунта `resetData()` обязан сбрасывать всё новое состояние контроллера.
   Работа сессии идёт в дочернем scope контроллера: на смене сессии отменяйте его запросы. `SessionStore`
   проверяет снимок адреса, токена и поколения перед обработкой ответа; старый `401` не снимает новый вход.
5. **Цвета — токены из `Theme.kt`** и сразу для обеих тем; значения берите из `global.css`. Не вписывайте hex в экраны
   (исключения — градиенты слоёв суток, как на сайте). `badgeColor` зависит от темы и потому `@Composable`.
6. **Шторки — только `AppSheet`.** Тело прокручивается; главная кнопка формы — `SheetFooter { SheetButton(…) }`
   (закреплена внизу, остаётся над клавиатурой). Свайп вниз за любое место закрывает шторку (вложенная прокрутка).
   Не сбрасывайте смещение шторки перед закрытием — она подпрыгнет; не возвращайте «жёсткий» сброс. При закрытии
   шторка снимает фокус, чтобы клавиатура уходила вместе с ней.
7. **Формы с вводом** сообщают `onDirtyChange`; закрывайте их через `controller.closeForm { … }`, чтобы случайный
   жест не терял текст («Отбросить введённое?»). После успешного сохранения сбрасывайте `formDirty`.
   У форм в `AppSheet` передавайте `closeBlocked = controller.discardAction != null`: отменённый свайп
   возвращает шторку на место, не пересоздавая введённый текст.
8. **Поля:** `SheetField` — «Далее» к следующему полю, у последнего `last = true`. Автофокус (`autoFocus`) —
   только у поиска: в формах клавиатура съедает полэкрана и требует второго «Назад». Даты — `DayChips`, `DueField`
   и `DatePickerSheet`, а не ввод «ГГГГ-ММ-ДД».
9. **Удаление события и задачи — с отменой** (`CalendarController.deferred`): запись скрывается, на сервере удаляется
   через 5 секунд, «Вернуть» отменяет. Одновременно ждёт одно удаление; перед выходом из аккаунта оно выполняется
   (`flushPending`). Исключения: повторяющееся событие спрашивает «серия или только этот день»; удаления и массовые
   правки ассистента подтверждаются карточкой чата, а не тостом.
10. **Ошибки и сообщения:** `controller.error` (плашка, сама исчезает, «Повторить» у запросов экрана) и `controller.toast`
    (короткое, может иметь кнопку). Не показывайте `AlertDialog`.
11. **Системная «Назад»** (`BackHandler` в `Shell`) закрывает по порядку: запрос «Отбросить?», шторки, экран; на главной —
    предупреждение и выход по второму нажатию за 2 секунды. Новая шторка добавляется и в `sheetOpen`, и в этот порядок.
12. **Нижняя панель** одна на приложение (`ActionBar`; в чате — `ChatBar`) и прячется, пока открыта шторка. Не кладите
    её содержимое в состояние контроллера.
13. **Экран «День» при смене даты — тот же экран** (`contentKey` в `Shell`): плашки и слои не пересоздаются.
    Новый маршрут между экранами проверьте на направление перехода (`depth`, `isForward`).

## Анимации и вибрация

- Пружины и пресеты — `Motion.kt`; нажатие — `Modifier.pressable` (ставьте первым в цепочке), появление каскадом —
  `Modifier.appear`. Выбор в переключателях — `SlidingKnob` + `rememberKnobBounds()` (`container()` на контейнере,
  `item(i)` на вариантах). Новые анимации сверяйте с `src/lib/motion.ts` и `*.module.css`.
- Не анимируйте дорогое на множестве элементов (размытие). Бесконечные анимации не добавляйте без причины:
  системный масштаб анимаций Android Compose учитывает сам, отдельного «reduce motion» в проекте нет.
- Вибрация — только через `Haptics` (`rememberHaptics()`): `tick` на выборе и листании, `toggle` на отметке,
  `confirm`/`reject` на действиях, `threshold`/`end` у жеста закрытия шторки. Не вешайте её на каждое нажатие.
  На вебе и JVM вызовы пустые.

## Доступность и размеры

- Иконочным и интерактивным элементам давайте `onClickLabel`/`contentDescription`; у карточек и ячеек — описание для
  скринридера («Планёрка, 10:00–11:00, Офис», «23 октября, 2 события»).
- Зоны нажатия ≥ 44dp. Известное исключение: стрелки ленты недели 36dp (в строку должны влезать семь дней).
- Подписи в узких местах: `maxLines`, `overflow = Ellipsis`; у кнопок в ряду не допускайте переноса слова посреди
  («Продолжит/ь» — признак того, что кнопки надо делать `weight(1f)` или короче).

## Как проверять работу

Для изменений в `kmp/shared`:

1. `./gradlew :shared:jvmTest` — тесты логики (календарь, привычки, подбор времени, SSE, напоминания, адреса).
   Новая логика — в `domain/` с тестом рядом.
2. `./gradlew :shared:compileKotlinWasmJs :androidApp:assembleDebug` — компиляция всех собираемых целей.
3. **Покажите изменение глазами.** Минимум — Wasm в браузере; для жестов, клавиатуры, вибрации и системной «Назад»
   нужен телефон. Сравнивайте с сайтом на 390×844, светлая и тёмная темы.

Не называйте проверку успешной, если её не запускали; iOS на Linux не собирается — так и пишите.

### Браузер (Playwright)

- Chromium запускайте с `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist --enable-webgl`
  (без WebGL Skiko падает) и `--disable-web-security` (CORS к чужому API) или с `CORS_ORIGINS` на сервере.
- Войти без UI: положите в `localStorage` ключи `token`, `user` (JSON) и `apiUrl`.
- Всё нарисовано на canvas — кликайте по координатам скриншота (CSS-пиксели). Касания шлите через CDP
  `Input.dispatchTouchEvent`: перетаскивание мышью шторки и списки не листает.
- **Не меняйте реальный аккаунт.** Подставьте API через `context.route('…/api/**')` с состоянием в памяти
  (GET/POST/DELETE), чтобы проверять создание, удаление и отмену без последствий.
- На Wasm эмодзи в тексте рисуются «тофу» (нет запасного шрифта), это особенность цели, а не баг Android.

### Телефон (adb)

- `adb install -r` → `adb shell am start -n app.calendar/.MainActivity`. Сборка Android берёт HTTP только в debug.
- Скриншот — `adb exec-out screencap -p > файл.png`; для плавности снимайте серию на устройстве циклом `screencap` и
  вытягивайте `adb pull`. Масштаб: на плотности 480dpi 1dp = 3px.
- **Перед каждым нажатием проверяйте, что в фокусе приложение** (`adb shell dumpsys window | grep mCurrentFocus`):
  «Назад» с главной выходит из приложения, пуш-баннеры и экран блокировки перехватывают нажатия, и тогда тапы попадают
  в системные «Настройки». Перед каждым сценарием запускайте приложение заново, а не полагайтесь на предыдущее состояние.
- На Xiaomi/HyperOS `adb shell input` работает только при включённом «Отладка по USB (настройки безопасности)».
  `adb shell input text` не вводит кириллицу — в тестовых названиях используйте латиницу.
- Данные реального аккаунта не меняйте без просьбы; созданные для проверки записи удалите. Реплики чата удалить
  нельзя — не шлите в чат лишнего.

## Известные подводные камни

- `BackHandler` лежит в отдельной зависимости `ui-backhandler` (указана в `shared/build.gradle.kts`); без неё ни одна
  цель не компилируется.
- `AnimatedVisibility` в `AppSheet` пересоздаёт содержимое при каждом показе — состояние жестов внутри него сбрасывается
  само, вручную после закрытия его обнулять не нужно.
- Ряд `ChoiceRow` с выбранным вариантом: чтобы выбранное было видно, у `ChoicePill` ставится `reveal = true`.
- Тосты и «Отбросить?» рисуются поверх шторок в конце `Shell`; новые оверлеи добавляйте туда же.
- Material 3 `DatePickerDialog` и `PullToRefreshBox` — экспериментальные API: нужен `@OptIn(ExperimentalMaterial3Api::class)`.
- Шрифт Inter подключён из ресурсов; `Res` генерируется при сборке (`app.calendar.resources`).

## Что не поддерживается (и не выдавайте за готовое)

Приём push на устройстве (шторка «Напоминания» настраивает сервер, но подписки приложения нет: сервер принимает только Web Push), голосовой ввод, картинки в чате, анкета знакомства,
многодневные события, вход Google/Outlook внутри приложения (открывается браузер), виджеты и ярлыки, планшетная
раскладка (ширина ограничена 480dp), иконка и сплеш уровня стора, настройки языка и 12-часового формата.
Подробности и статус экранов — в [PLAN.md](PLAN.md) и этапе 18 в [docs/ROADMAP.md](../docs/ROADMAP.md).

## Офлайн и напоминания

- `api/Outbox.kt` хранит мутации событий и задач, `ReadCache` в `api/OfflineMerge.kt` — последние ответы.
  Владелец очереди — адрес API + id пользователя (`SessionStore.ownerKey`), а не один id. Replay использует
  снимок сессии и прекращается при её смене; ответ старого create не должен менять привязки id новой очереди.
  Старая очередь с владельцем только по id не переносится в нового владельца: её сервер нельзя проверить.
  Проверяйте смену аккаунта, временные id и повтор после восстановления сети; Background Sync нет.
- `ui/RemindersSheet.kt` редактирует серверные настройки уведомлений, тихие часы и свои напоминания,
  показывает устройства. Это не регистрация нативного устройства для Web Push: доставка остаётся в PWA.
- Подсказки названий задач — `domain/TaskTitles.kt`; веб-аналог — `src/domain/taskTitles.ts`.
  При изменении правил сверяйте обе реализации и их тесты.

- SSE без завершающего `done` — обрыв, даже если HTTP-поток закрылся без сетевой ошибки.
  Не убирайте частичный ответ из чата до успешного завершения.
- Logout ждёт все DELETE с отменой, в том числе уже начавшиеся после пятисекундного таймера.
  Регрессии с задержанными ответами — `SessionRegressionTest.kt` и `OutboxTest.kt`.
