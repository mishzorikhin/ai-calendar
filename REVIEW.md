# REVIEW.md — чек-лист ревью

Для людей и агентов, которые ревьюят изменения в этом репозитории. Общие правила — в
[AGENTS.md](AGENTS.md), правила Go — в [server/AGENTS.md](server/AGENTS.md).
Выводы привязывайте к изменённому коду и конкретному сценарию; отличайте регрессию от уже известного
ограничения. Для каждого замечания укажите место, последствия и способ проверки.

## Блокирует мерж

- **Корректность:** гонки, таймеры без очистки, устаревшие замыкания, неверные даты и часовые пояса,
  месяц с 0 в TS и с 1 в `/api/month`, расчёт свободных окон по предыдущему дню из placeholder-кэша.
- **Контракт API:** поле изменено только в Go или TS/DTO; метод отсутствует в `http.ts` или `local.ts`;
  изменён `store.Store`, но одна из реализаций или её тесты забыты.
- **Доступ:** хендлер данных без `s.authed`, владелец из тела запроса, доступ к чужим данным,
  секреты в ответах/логах/git, запись файлового хранилища без блокировки и отката при ошибке.
  У публичных health/auth/OAuth callback/ICS feed собственные правила доступа — см. `server/AGENTS.md`.
- **Валидация:** вход не проверен, в ответе внутренние детали, инструменты LLM обходят проверки хендлеров.
  Изменение поведения без теста существенной ветки.
- **Данные мимо слоя API:** `fetch` в UI, импорт календарных моков в экран, несогласованные query keys.
  Оптимистичный `setQueryData` допустим с отменой запросов, откатом и последующей инвалидацией.
- **Офлайн:** новая мутация теряется/повторяется неверно, `401` или `5xx` уничтожают очередь,
  `424` ошибочно повторяется бесконечно, действие одного аккаунта отправляется от имени другого.
- **Внешние календари:** запись события мимо `createEventSynced`/`updateEventSynced`/`deleteEventSynced`,
  обход `readOnly`, HTTP календарей мимо `calsync.Net`, секреты без `secret.Box`,
  потеря стабильных id при синхронизации, неправильный пояс/all-day/повторы.
- **Совместные задачи:** обход `shareTaskWith`, повторный шаринг старого упоминания вместо `newMentions`,
  неверные права владельца/участника, повторные уведомления без нового участника.
- **Типы и стили:** добавлены `eslint-disable`, `!important`, `as any` или необоснованное `!`
  вместо проверки потенциального `undefined`.
- **Доступность:** иконочная кнопка без имени, модалка мимо `BottomSheet`, скрытый интерактивный слой
  без `inert`, потеря фокуса/Escape, текст ниже нормы контраста, зоны нажатия меньше минимума проекта.
- **PWA:** кэш/заголовки/обновление worker изменены без проверки обновления и офлайна на обычной сборке.
- **Проверки:** применимые проверки падают, результат скрыт или пропуск назван успехом.
  UI-изменение без браузерной проверки на 390×844 и 375×667 при изменении вёрстки.

## Сценарии для сессий, PWA и ассистента

Текущие ограничения описаны в корневом `AGENTS.md`; изменение документации само по себе их не исправляет.
При изменениях этих областей проверяйте:

- A создаёт событие/задачу офлайн → выходит → входит B → сеть возвращается:
  действия A не должны отправляться от B, приватные ответы A не должны показываться B.
  Проверяйте отдельно QueryClient, Cache Storage и IndexedDB.
- Одновременно открыты две вкладки и работает worker: нет потери операций и дублей replay.
  Сопоставление полей `dedupe` не является серверным ключом идемпотентности.
- Истёкшая сессия: отдельно обычный запрос, SSE чата и повтор очереди; ошибки не теряют ожидающие изменения.
- `VITE_API_URL` указывает на другой домен: отдельно повтор страницы и Background Sync
  (worker сейчас вызывает `flush('')`).
- AI пытается удалить без подтверждения. Сейчас подтверждение задано промптом, серверный `runTool`
  его не проверяет. Если PR вводит подтверждение, тест должен доказывать отказ до разрешения.
- SSE: частичные кадры, ошибка/обрыв, fallback модели, обновление кэшей после tool call;
  middleware сохраняет `Unwrap` для `http.ResponseController`.

## Проверки по области изменения

- Фронтенд: `npm run check` и `npm run build`; однофайловый режим — `npm run build:single`.
- Go (из `server/`): `test -z "$(gofmt -l .)" && go vet ./... && go test -race ./...`.
- PostgreSQL (из `server/`): `TEST_DATABASE_URL=… go test -race ./internal/store -run TestPostgres -count=1`.
  Тесты выполняют TRUNCATE: только одноразовая БД. Без переменной они пропускаются, в текущем CI БД нет.
- PWA: production-сборка на localhost/HTTPS, обновление worker, офлайн-чтение и replay.
  Саму очередь из страницы можно проверять в dev; worker и Background Sync — на сборке.
- Поставка: сборка Docker, запуск и `/api/health`; проверку данных выполняйте на тестовом окружении.
- Только документация: форматирование, ссылки/пути, соответствие команд и описаний исходникам.
  Тесты и сборка приложения не обязательны. Невыполненные проверки и причины укажите явно.

## Обратить внимание

- Дизайн: токены вместо литералов цвета, единые радиусы и отступы, минимум зоны нажатия по `AGENTS.md`.
- Анимации: `useReducedMotion` для бесконечных, без массового blur, корректный ref у детей
  `AnimatePresence mode="popLayout"`.
- Компоненты с несколькими независимыми частями и размером больше ~150 строк стоит разделить.
- Тексты — на русском, короткие, с «ёлочками» и «ё».
- Обновлены README и агентские инструкции, если менялись команды, структура, API или ограничения.
- Коммит содержит только согласованные изменения; push не переписывает историю и не подменяет деплой.
